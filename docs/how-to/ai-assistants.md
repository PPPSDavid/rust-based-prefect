# How to use IronFlow with AI coding agents

IronFlow’s HTTP API and JSON CLI are designed so shell-capable assistants
(Claude Code, Cursor, Codex, custom agents) can inspect and operate the
control plane without scraping the UI.

Roadmap (MCP server, planner tools, opt-in write tools):
[`docs/plans/agent-native-roadmap.md`](https://github.com/PPPSDavid/rust-based-prefect/blob/main/docs/plans/agent-native-roadmap.md).

## Prerequisites

1. API server running (see [How to run the server and UI](server-and-ui.md)).
2. Optional Basic auth: set `IRONFLOW_SERVER_API_AUTH_STRING` on the server and
   matching `IRONFLOW_API_AUTH_STRING` for CLI clients
   ([secure self-hosted](secure-self-hosted.md)).
3. Point the CLI at the API:

```bash
export IRONFLOW_API_URL=http://127.0.0.1:8000
# optional:
# export IRONFLOW_API_AUTH_STRING='user:pass'
```

Discovery surfaces:

| Surface | URL / command |
| --- | --- |
| OpenAPI | `GET /openapi.json` or `http://127.0.0.1:8000/docs` |
| Docs sitemap for agents | Hosted `llms.txt` (generated by `docs/gen_llms.py`) |
| Health | `GET /health` |

## Prefer structured CLI over ad-hoc `curl`

All of these print **JSON** to stdout (errors on stderr, non-zero exit):

### Raw passthrough

```bash
ironflow api GET /api/flow-runs
ironflow api GET /api/flow-runs --query state=FAILED --query limit=10
ironflow api POST /api/deployments/<id>/run --data '{}'
ironflow api POST /api/flow-runs/<id>/pause --data '{"mode":"drain"}'
ironflow api POST /api/deployments --data @body.json
```

Methods: `GET` / `POST` / `PATCH` / `DELETE`. Auth headers come from
`IRONFLOW_API_AUTH_STRING`.

### Flow runs

```bash
ironflow flow-run ls --state FAILED --limit 20
ironflow flow-run inspect <flow-run-id>
ironflow flow-run task-runs <flow-run-id>
ironflow flow-run logs <flow-run-id> [--task-run-id ...] [--level ERROR]
ironflow flow-run events <flow-run-id>
ironflow flow-run dag <flow-run-id> --mode logical   # or expanded
ironflow flow-run cancel <flow-run-id>
ironflow flow-run pause <flow-run-id> --mode drain    # or terminate (required)
ironflow flow-run resume <flow-run-id>
ironflow flow-run retry <flow-run-id>                 # deployment-backed only
```

Pause always requires `--mode` (`drain` or `terminate`). Details:
[How to cancel, pause, and resume](cancel-pause-resume.md).

### Deployments

```bash
ironflow deployment ls
ironflow deployment inspect my-deployment          # name or UUID
ironflow deployment run my-deployment --param n=2
ironflow deployment run my-deployment --parameters '{"n": 2}' --idempotency-key once-1
```

`deployment run` returns the run **handle immediately** (no wait loop yet;
`--wait` is planned for a later phase).

### Catalog & concurrency

```bash
ironflow flow ls
ironflow flow inspect my-flow
ironflow gcl ls
ironflow gcl inspect db
```

## Live updates

SSE streams (for clients that can consume them):

- `GET /api/stream/flow-runs`
- `GET /api/stream/flow-runs/{id}`

Otherwise poll `ironflow flow-run inspect <id>` or
`ironflow api GET /api/flow-runs/{id}/events`.

## Safety notes for agents

| Action | Prefer | Notes |
| --- | --- | --- |
| Inspect / diagnose | `flow-run` / `deployment` / `api GET` | Read-only |
| Trigger / cancel / pause | Explicit user intent | Mutations |
| Pause | Always pass `--mode` | No ambiguous default |
| Cancel | Terminate semantics | Prefer process task runners for hard kill |

Coming next (roadmap Phase 1): a **read-only** `ironflow-mcp` server so MCP
clients get the same inspect tools without shell access. Mutations will stay
CLI-first by default (Prefect’s posture).

## Suggested agent workflow

1. `ironflow flow-run ls --state FAILED --limit 10`
2. `ironflow flow-run inspect <id>` then `logs` / `events` / `dag`
3. Fix code or config; `ironflow deployment run <name>` to verify
4. For one-off API gaps, `ironflow api …` against `/openapi.json` routes
